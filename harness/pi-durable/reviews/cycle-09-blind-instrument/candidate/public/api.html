Public product interface

Booking record API

JSON over HTTP. All paths below begin with /api/houses/HOUSE_ID/, except house creation. POST bodies use Content-Type: application/json. Refused domain requests return status: "refused", a reason and the policy version. Invalid input returns HTTP 400. Requests are applied atomically to a persistent record before the server responds.

This is a local cooperative workbench. The house and acting household/role are explicit working context, not authenticated credentials. Manager-mediated bookings are recorded at the manager's desk, not automatically sent to an outside manager. Do not expose this administrative build to an untrusted network.

Quick example

POST /api/houses/demo/bookings
{"household":"12","role":"tenant","resource":"8","weekday":"Tuesday","start":"17:00"}

GET /api/houses/demo/views
GET /api/houses/demo/views?date=2030-01-08
GET /api/houses/demo/bookings/BOOKING_ID/history

POST /api/houses/demo/releases
{"household":"12","bookingId":"BOOKING_ID","date":"2030-01-08","mode":"FREE"}

POST /api/houses/demo/releases/OFFER_ID/take
{"household":"3","role":"tenant"}

Use a future Tuesday for an occurrence. The current house clock is available from GET config. Calendar times are named local calendar values interpreted on the workbench's UTC clock. There is no floating-hour or bare timestamp slot identity: a dated slot is always {date, resource, start}; a recurring one uses {weekday, resource, start}.

Endpoints

Method / pathPurpose / body
GET /api/housesAvailable houses and their effective policies.
POST /api/housesCreate {id,name,resources,policy,now?}. Separate empty booking record. See configuration example below.
GET configComplete house configuration, immutable policy history and booking record; effective policy and current now.
GET routeBooking channel, operator, booker roles and whether a resident queue is enabled.
GET scheduleConfigured weekly windows with resource, weekday, start, end, time class, group, free/held and household.
GET bookingsConfirmation records including ended holdings. Dates and end times are derived from configured windows.
POST bookings{household,role,resource,weekday,start} for a weekly holding; replace weekday with date for a dated booking. Responses identify the governing policy.
POST bookings/:id/give-up{household}. Ends the holding, preserving its history. No future standing charge for this holding.
GET bookings/:id/historyConfirmation, refusal and transition evidence for a booking/decision identity.
GET views?date=YYYY-MM-DD{postedList,heaterSchedule,billingSignals} derived together. Specify a date for occurrence takers and releases; omit it for a standing/upcoming overview. Historical standing fees can be read by date; no separate list, timer or bill is stored.
GET releasesOne-week offers and their current lifecycle state.
POST releases{bookingId,household,date,mode:"FREE"|"SALE"}. Original household keeps its holding and normal fee.
POST releases/:id/take{household,role}. One atomic winner, before occurrence start. SALE emits a distinct resale signal naming the price reference; FREE has no taker charge.
POST releases/:id/withdraw{household}. Original holder only, untaken offer only, before start. Untaken offers become unclaimed at start.
GET queue?group=AFIFO accepted requests within an eligible group.
POST queue{household,role,group}. Only self-service houses expose this resident route.
POST queue/:id/withdraw{household}. Notice clocks remain fixed after the queue empties.
POST notices/evaluate{group}. Checks full standing capacity + queue + multi-holder. Repeated evaluation cannot issue a second active notice to that household.
GET noticesExact choose/lapse instants, pinned policy version, current choice right, selected booking, offered-to household and pending successor.
POST notices/:id/choose{household,bookingId}. Holder before choose deadline; queue-head after it. Choice does not end the holding.
POST notices/:id/claim{household}. Queue-head confirms a pending succession; original holder stays until lapse.
POST notices/:id/decline{household}. Offer passes to next eligible queue entry. Selected holding still lapses if nobody takes it.
GET policiesAll immutable rule versions including authority and effective instant.
POST policies{authority,effectiveAt,...changedFields}. Authority must match the current rule. New decisions use the effective version; old decisions/deadlines do not change. Resource calendars may be revised here.
GET clockCurrent instant and controlled-clock status.
POST clock{now:"2030-02-01T10:00:00Z"}. Administrative forward-only time control; expiry/lapse occurs on the next read or mutation. Without a controlled clock, real time is used.
GET historyHouse-wide decision and transition audit.
POST disputes{bookingId,role,reason}. Configured first-stop role only. Response preserves that booking's confirmation, changes and governing versions.
GET disputesRecorded disputes and their evidence snapshots.

Independent house configuration

POST /api/houses
{
  "id": "house-a", "name": "House A", "now": "2030-01-01T10:00:00Z",
  "resources": [{
    "id": "8", "name": "Dressing room 8", "sauna": "F", "group": "A",
    "duration": 90,
    "days": ["Tuesday"], "starts": ["17:00", "18:30"]
  }],
  "policy": {
    "authority": "board", "route": "self-service", "bookerRoles": ["tenant"],
    "operatorRole": "manager", "billingRole": "billing", "disputeRole": "manager",
    "chooseDays": 14, "noticeDays": 30,
    "standingPriceRef": "house standing tariff",
    "salePriceRef": "house resale tariff", "classCaps": {"family": 1}
  }
}

For time-class calendars, replace days and starts with "windows": [{"weekday":"Tuesday","start":"17:00","timeClass":"family"}]. Group names determine queue eligibility and scarcity scope. They never cross house boundaries. Booker roles are explicit per request. A class cap counts active/upcoming confirmed dated bookings (and recurring rights) of that class only.

Limits

No equipment commands, numeric resale prices, sale-proceeds distribution, payment collection, invoice delivery, no-show penalties or third-hand subtenant policy are invented. Existing-booking migrations across policy revisions are outside this cut. The sample ph 8 calendar includes the documented Tuesday; other sample windows are explicit illustrative configuration, not an assertion about the cooperative's full calendar.

A notice without a selected holding retains the queue-head choice right after the choose deadline; no undocumented default choice is made. Use choose before the selected holding can lapse.
