# Pi durable Löyly cycle: production readiness

This branch explores replacing the ORC **cycle controller** with Pi durable while keeping the accepted ORC runner available as the reference. The original Babashka/shell harness remains the instrument and gate; ORC may later analyze a scrubbed audit export, but Pi execution must never be represented as ORC ticks. The throwaway prototypes proved control flow with fixture agents. Fixture scores are not product evidence.

## First dependency now available

`bb harness/loyly-run cut --commit REV --state-dir DIR --run-id ID` prepares the same scratch cut as the accepted `start` command without launching ORC. It refuses an existing state directory and writes `DIR/evidence/cut.json` with the source, base and cut commits. The existing `start` path is unchanged.

`node harness/pi-cycle/prepare.mjs --state-dir DIR --commit 40-HEX --run-id ID --checklist-sha256 64-HEX` owns cut, self-check, fence and checklist as Pi durable phases. Every recorded transition is an audit entry in the same commit as its checkpoint. It verifies a completed cut/fence when resuming, refuses a partial external effect, and compares the derived checklist bytes with the approved digest before returning the room. The test on `a733b7e` returned cut `cd24dd8`, 11 items and checklist SHA-256 `4acbadbce0e08cafd19ac89d2a0d909a564abd242ffecdb06b6184a1bbe631cc`. Reopening the same store returned the saved result without replaying phases. Reopening it with a changed approval was refused; a fresh run with an all-zero digest stopped at `checklist refused` with exit 1.

The next implementation step is to replace the fixture builder in a Pi cycle task with `.pi/harness/bin/builder.sh`, using a stable session ID and process cancellation, then run one real app candidate through the unchanged legacy gate. A live grader and scoring follow only after the candidate and room boundary are proved.
